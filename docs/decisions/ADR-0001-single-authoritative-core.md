# ADR-0001 一个权威 Core，Windows 与本地浏览器并行产品化

状态：Accepted as product direction · 2026-10-20 · 决策角色：产品负责人

## 问题
SRW 需要 Windows WPF/WebView2 与 HTML/Browser 两种本地入口同时发展。若分开实现业务内核、SQLite 和 Job Engine，未来必须解决复杂且脆弱的双向同步、冲突、版本漂移、审计断裂。

## 决定
保留现有 C11 核心；两种载体使用统一 Core/API、数据工作区、业务规则和审计。工程并行推进，要求分别达到验收门槛、争取同期交付。优先复用现有前端，不进行全面 UI 重写。

## 已考虑方案
A. 先 Windows GA，再单独开始 Web —— 风险低，但浪费 E1–E5 的技术基础且可能引起后续架构返工。
B. 两端各自独立数据库后同步 —— 双写和历史决定问题复杂，放弃。
C. 共用 Core、多载体并行、共同里程碑 —— 采纳。

## 验证依据
探索 E1/E3/E4/E5 与 Native SOURCE Lab 分别证明部分读写、事务 CAS、Core owner、会话附着和真实 WPF/Browser 共同读取能力。尚未证明正式生产双写、权限和完整发行，必须继续实测。

## 后果与风险
正式双端使用需要 Core Supervisor、一次性授权、同事务版本校验、后台任务唯一所有权及严格本地 HTTP 防护。Windows 和 Local Web 两个工件不能互相代替验收。

## 可重新讨论条件
有可重复证据证明统一 Core 在核心招聘业务、目标资源/性能或离线使用上不可行，或产品负责人批准改变目标用户/部署边界。
